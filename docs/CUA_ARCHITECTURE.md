# Windows CUA 架构

## 设计目标

在 Windows 上实现可信的 Computer Use Agent：

- 真实屏幕观察与操作
- 任务契约驱动
- 监督循环与权限闸门
- 可审计、可恢复、不假绿

## 最小可行闭环

1. **Observer** — 获取当前屏幕状态（截图、窗口列表、焦点窗口）
2. **Decision** — 根据任务契约与当前观察决定下一动作
3. **Action** — 执行鼠标/键盘/窗口操作（受闸门约束）
4. **Verify** — 再次观察，确认动作效果
5. **Persist** — 写入任务状态与审计日志

## 权限模型（对齐现有 sentinel）

| 级别 | 说明 | 示例 |
|------|------|------|
| L0 | 只读 | 截图、查询窗口 |
| L1 | 提醒 | 通知用户 |
| L2 | 白名单可逆 | 写指定目录下的文件 |
| L3 | 人工一次性批准 | 删除、系统设置、网络请求 |

闸门必须由代码强制，不能只靠提示词。

## 任务契约（草稿）

```json
{
  "id": "task-001",
  "goal": "打开记事本并输入文本",
  "steps": [
    {"action": "open", "target": "notepad"},
    {"action": "type", "text": "hello"}
  ],
  "success": "窗口存在且含指定文本",
  "onFailure": "retry_or_abort"
}
```

## 与现有设施的关系

- 复用 sentinel 的闸门思路与审计机制
- 监控大屏可接收 CUA 事件（通过 /api/event）
- cua-lookout 可继续作为外部健康检查

## 实现约束

- 优先零 npm 依赖
- Windows 原生 API / PowerShell / 可访问性接口
- 所有动作必须可被监督代理拦截
- 状态存储在本地，不依赖外部服务
