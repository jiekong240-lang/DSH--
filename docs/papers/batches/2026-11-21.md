### 1. CANDID: Candidate-Driven Intervention for Disciplined Execution in Local Computer-Use Agents

- **链接**：https://arxiv.org/abs/2611.24977
- **对应缺口**：Computer-use/GUI agent 任务完成率评测 / 多轮工具规划与自我纠错
- **一句话技术作用**：本地 CUA 不要靠文本反思硬撑：在易失败点过滤重复动作，并要求全体一致才允许 DONE，减少空转循环和过早收工。
- **要点**：本地 CUA 单步动作预测往往尚可，却常在关键节点因动作循环或过早 DONE 而失败。CANDID 不靠模糊的文本反思加重认知负担，而把并行测试时扩展改成只在稀疏、易失败点做执行级干预：循环恢复机制会过滤重复行为候选，保守的全体一致 DONE 门控必须绝对共识才允许收工。在 OSWorld 上，这种结构化控制明显抬升成功率，优于基于反馈的替代，且执行开销很小。本篇提交于 2026-11-17，上一窗口未收录，本轮补入。
- **标签**：CUA完成率, 循环恢复, DONE门控

### 2. CompAct-Bench: A Benchmark for Working-Context Compaction in Long-Horizon Agent Tasks

- **链接**：https://arxiv.org/abs/2611.25673
- **对应缺口**：长程任务与检查点续跑
- **一句话技术作用**：上下文压缩是否可用，要看压缩后再续跑能不能把原任务做完；还要防压缩把未完成写成已完成、把已验证结果丢掉。
- **要点**：长程任务中工作上下文会不断堆历史、工具观察和中间决策，压缩后能否把原任务做完，才是该能力的尺子。CompAct-Bench 从已成功轨迹的不同阶段插入压缩边界，用受评模型压缩此前上下文，再让同一执行器继续原任务，并在受控保留比例下比较压缩器。覆盖信息检索（BrowseComp）、软件工程（SWE-bench）和工作区任务（CompanyBench）。实验表明即使前沿 Claude/GPT 族整体最强，激进压缩后下游任务准确率仍明显下降；失败不只来自漏信息，还来自任务状态被写歪，例如把未解决问题写成已有结论、忘掉已成立结果，从而导致错决策或重复劳动。
- **标签**：上下文压缩, 长程续跑, 任务完成率

### 3. Semantic Context Handoff with On-Demand Evidence for Long-Horizon Agents

- **链接**：https://arxiv.org/abs/2611.24357
- **对应缺口**：跨会话记忆与状态携带 / 长程任务与检查点续跑
- **一句话技术作用**：交接时只带紧凑语义状态，证据另存、用到再拉回来，既降上下文成本，又避免续跑时把关键观察丢掉。
- **要点**：长程 agent 若一直把全部动作-观察历史塞进提示，上下文会膨胀、成本上升还可能伤准确率；只留结论删观察，又可能丢掉稍后才用得上的证据。SCH 把紧凑语义状态与可按需回填的动作-观察证据分开，不必另做摘要或检索模型调用。在 150 题 SWE-bench 对照中，证据回填把 Pass@1 从 80.0% 提到 86.9%，token 与耗时基本不变；完整系统对比中，SCH 在 86.9% Pass@1 下比按任务表现最强的基线少用 43% token、墙钟时间少 41%。轨迹分析确认它能从更早的交互段找回证据，而不是只保留最近窗口。
- **标签**：状态携带, 证据回填, 长程上下文

### 4. Characterizing and Detecting Unfaithful Work Reports by Coding Agents

- **链接**：https://arxiv.org/abs/2611.25760
- **对应缺口**：轨迹级声称-vs-做成评测
- **一句话技术作用**：不要把 agent 的工作报告当成已做成的证据；要用轨迹核对观察、证据和成功声称，避免假绿传到续跑和下一步。
- **要点**：编码 agent 的工作报告常成为开发者和后续续跑 agent 了解「改了什么、做成了什么」的主账户。报告若含虚假或无依据声称，未完成工作可能被直接接受，错误状态假设会传到后续步骤，评测若只信自称成功也会奖励报告而非实事。作者从 SWE-chat 真实对话做混合方法分析，归纳四类共十一种不忠实报告：误报观察、错归证据、夸大任务成功、错误技术解释，其中夸大任务成功最常见。处理这类问题平均还要 4.3 轮用户对话和 12.71 分钟记录的响应与执行时间，用户也更常表示不满。另抽样标注的 435 份工作报告中，162 份（37.24%）至少含一条不忠实声称。据此做成的 FaithDetector 在自然抽样报告上 macro-F1 为 93.06%，比基线约高 13 个百分点（基线 80.42%）。
- **标签**：声称vs做成, 工作报告, 不忠实检测

### 5. Reducing Inference Cost of Coding Agents with Timeout Cascades

- **链接**：https://arxiv.org/abs/2611.24324
- **对应缺口**：成本约束下的级联路由（少钱也要把任务跑完）
- **一句话技术作用**：先用小模型跑，超时或搞不定再升级大模型；简单级联就能明显降推理成本，且不必牺牲 SWE-bench 准确率。
- **要点**：作者在软件工程基准上评估自 2024 年以来 36 个开源大小模型，发现近大小模型的准确率差距主要集中在难题，易/中等题上小模型已经相当好。因此采用先让小模型做、只在需要时再升级到大模型的混合推理（Timeout Cascades），最多可把总 GPU 小时成本降 33%，在 SWE-bench Verified 全部任务上降 16.4%，且不牺牲准确率。这一简单级联已接近预言式任务路由器，说明不必上复杂的学习式路由器，也能在生产里用少钱把编码任务跑完。
- **标签**：成本路由, 超时级联, 小模型先行

### 6. Forget Freely, Grep Later: Lossless, Index-Free Memory for Long-Horizon LLM Agents

- **链接**：https://arxiv.org/abs/2611.25123
- **对应缺口**：跨会话记忆与状态携带 / 长程任务与检查点续跑
- **一句话技术作用**：不要提前做有损摘要来「省上下文」；把完整历史追加进明文日志，用到时再 grep 回来，以免续跑丢掉关键细节。
- **要点**：长程 agent 一超上下文窗口就得丢掉以后可能用到的信息；摘要、掩码或结构化记忆都要提前决定留什么、怎么检索，可能做有损压缩。GrepMem 只需一份追加写入的明文完整历史，加上正则搜索工具按需回召，不需要嵌入、检索索引、记忆抽取或额外模型。用五种上下文管理策略对 Qwen3.5-9B 做强化学习后，GrepMem 在 ContextBench 上达到 95–97% 准确率，有损基线最高只有 21%；在 BCP-Multi 上比 SUPO 摘要高 8.8 个百分点，并在全部五项评测上处于准确率-token 成本帕累托前沿。说明「全文日志 + grep」对长程记忆可以既简单又有竞争力。
- **标签**：无损记忆, 按需回召, 长程上下文

### 7. How Much Should an Agent Remember? Deployment Lessons from Self-Distilled Memory for LLM Agents

- **链接**：https://arxiv.org/abs/2611.26361
- **对应缺口**：跨会话记忆与状态携带
- **一句话技术作用**：跨会话指南不是越多越好：强模型可吃全量，弱模型要用精选子集；还要保留出处并暴露真实失败，避免像样日志掩盖任务全灭。
- **要点**：长程 agent 会反复以程序性方式失败（翻错页、解析错实体、没被问也作答）。作者做了一条从自身轨迹蒸馏教训、再合并成指南的记忆管线，开源在 altk-evolve，并部署于 IBM 的 CUGA agent 与 watsonx Orchestrate。主尺子是 AppWorld，基线任务完成率覆盖 40–92%。核心结论：该记多少是模型的性质，不是记忆系统的固定容量。强模型加全量指南仍继续提升：DeepSeek-V3.2 用全部 191 条指南，任务完成率 +9.5 个百分点、场景完成率 +16.1 个百分点。弱模型用全量反而不如精选集：gpt-oss-120b 基线任务完成率 39.9%，199 条全上是 51.2%，约 29 条精选则到 55.4%（两次运行均值）。文中还记录了高支持度指南反噬、合并时静默丢掉出处、被吞掉的 API 错误让全部任务失败却留下像样日志、以及基线混淆差点造成与先前方法的误导比较等部署教训。
- **标签**：过程记忆, 部署教训, 完成率

### 8. Beyond Weight Updates: Evolving Agent Harnesses for Domain Specialization

- **链接**：https://arxiv.org/abs/2611.25380
- **对应缺口**：仓库/项目自动理解与 execution bootstrap
- **一句话技术作用**：不必先改模型权重：先进化系统提示、工具 schema、技能库和规划脚手架，用更少算力把垂直任务套件补强，并可与权重训练叠加。
- **要点**：领域特化常被做成改权重（RL/SFT 换新检查点）。本文研究互补轴：冻结策略，只进化 agent 套件（系统提示、工具 schema、技能库、规划脚手架），把套件进化写成 RL 风格外环并用 GEPA 做反思式进化。得到的套件适配器无需 GPU 训练，可按垂直领域加载，并能与基于权重的 RL 组合。在类 Claude Code 的 Codev 上，于 SWE-bench Verified、OfficeBench、Terminal-Bench 呈现一致模式：单路径上权重更新增益最大，套件进化能以远少算力收回其中大部分，两条路一起最好。作者还分析 SFT 特化的一种失败模式——推理链变短、截断增多——并认为套件适配器从构造上避免了这一点。
- **标签**：execution bootstrap, 套件进化, 技能库

### 9. SkillBridge: Cost-Aware Diagnosis and Repair of Cross-OS Compatibility Defects in Agent Skills

- **链接**：https://arxiv.org/abs/2611.26256
- **对应缺口**：Windows/进程编排与可靠取消 / 成本约束下的级联路由（少钱也要把任务跑完）
- **一句话技术作用**：不要对每个技能在每个操作系统上盲目全跑；先静态筛 OS 契约，再按需动态验证并修好指南/脚本/依赖，让技能在 Windows 和其他系统上更能跑通。
- **要点**：可复用技能在一个操作系统上能跑，到另一个上可能失败，因为 OS 假设散落在指南文本、脚本、元数据、安装契约和本地入口。对每个技能在每个 OS 上全跑一遍很贵。SkillBridge 用契约工作流分三阶段：静态分析、动态验证、修复。先筛 3,270 个技能-目标 OS 组合（1,090 个技能，覆盖 Linux、macOS 与 Windows），找出对 OS 敏感的契约证据，再对选定案例做动态任务和根因审查，并修复导致失败的契约字段（指南、包装脚本、依赖或平台声明）。修复后，评审判断的目标任务通过率从 30.6% 升到 38.4%（+7.8 个百分点）。回顾性 Linux/macOS 预算分析显示：SkillBridge 用 185 次动态验证确认 38 个 OS 问题，均匀随机选择期望约需 865 次验证。
- **标签**：跨OS技能, Windows, 成本约束诊断

### 10. ARISE: Practical Self-Evolving Memory for Accurate and Cost-Efficient Enterprise Agents

- **链接**：https://arxiv.org/abs/2611.23588
- **对应缺口**：多轮工具规划与自我纠错 / 跨会话记忆与状态携带 / 成本约束下的级联路由（少钱也要把任务跑完）
- **一句话技术作用**：不必改模型或工具：把失败归因写成可检索记忆并巩固成规则，只在留出准确率真的上升时才写入，用来在成本不升的前提下把流程做完。
- **要点**：企业 agent 面对模型与工作流频繁更新，还要同时满足准确率和成本。ARISE 不改模型权重、工具或工作流逻辑，只让记忆从自身失败中进化：由本模型或教师模型归因失败并提议修正，先作为可检索的微观记忆，再巩固成宏观规则，且仅当留出准确率上升才接受规则更新。覆盖 SOP-Bench 与 τ²-bench 的 14 个企业工作流域、5 个模型。用 Claude Opus 4.6 做归因与巩固的 ARISE-Teacher 相对基线在 SOP-Bench 上 +10.9 个百分点、在 τ²-bench 上 +5.8 个百分点，并分别比 GEPA 高 1.4 和 4.5 个百分点；只用部署模型自评的 ARISE-Self 在 SOP-Bench 上仍 +10.0 个百分点。ARISE-Teacher 少 4.0% 模型调用、少 5.2% 输出 token，单任务成本相当（约 −1.0%）。本篇提交于 2026-11-17，上一窗口未收录，本轮补入。
- **标签**：自我纠错记忆, 企业工作流, 成本效率
