### 1. Do Verifier Judgments Survive Abstraction? Measuring Verification Transport for LLM Agent Evaluation

- **链接**：https://arxiv.org/abs/2611.18471
- **对应缺口**：轨迹级声称-vs-做成评测
- **一句话技术作用**：给 claim-gate / lookout 补一条尺子：压缩历史、委派或组合工具后，法官判决必须仍能站住；不能只看未压缩轨迹上的准确率，出处丢失时宁可弃权也不要假绿。
- **要点**：Verification Transport 在任务、实现轨迹、结果、真值和协议都冻结时，比较原生、抽象、还原三种视图上的判决稳定性。四个基准、七个法官骨干、四种协议、三种抽象边界下，宏观抽象与委派的传输失败约 31%；直接判决更容易给错结论，证据锚定和审慎协议更常在证据不足时弃权。还原对应执行出处可挽回 85.5% 的传输失败，出处残缺时挽回更低。
- **标签**：声称vs做成, 抽象传输, agentic法官

### 2. HerAgent: A Block-Level Checkpointing Harness for Coding-Agent Environment Setup

- **链接**：https://arxiv.org/abs/2611.18443
- **对应缺口**：仓库/项目自动理解与 execution bootstrap / 长程任务与检查点续跑
- **一句话技术作用**：把项目环境搭建的进度控制从「一条命令或整段脚本」改成语义块级检查点：失败只回滚污染块、保住已验证进展，让后续编码任务真正进得去可执行环境。
- **要点**：编码 agent 需先搭好可执行环境才能测、修、验证补丁。HerAgent 用语义 setup block 统一执行、校验、检查点、修复与回滚。在四个环境搭建数据集上对六个先前 agent 比较，每组都提高了搭建成功率，Installamatic-Bench 从 52.0% 升到 85.0%，SetupBench 从 46.3% 升到 70.4%，搭建成本最多降 94.5%。
- **标签**：检查点续跑, execution bootstrap, 环境搭建

### 3. Co-Sight Harness: Externalized Control Assets and Deterministic Enforcement for Long-Horizon Business Agents

- **链接**：https://arxiv.org/abs/2611.17696
- **对应缺口**：长程任务与检查点续跑 / 轨迹级声称-vs-做成评测
- **一句话技术作用**：把超长工作流的定义、状态和验收门放到模型上下文之外强制执行，并用独立审计员看轨迹是否真做成；用来把 SOP/resume-task 从「靠模型记住流程」升级成可版本化、可回归的运行时控制。
- **要点**：不改骨干模型，将工作流定义、状态和领域知识外置为可版本化控制资产，用状态机和可机检验收门在运行时强制执行。三个超过 200 步的已部署工作流中，Domain A 的 120 例端到端集上无人值守完成率从 50% 升到 100%，检索召回从 56% 升到 91.67%，端到端时延从 440 分钟降到 159 分钟，情景分析召回从 45% 升到 93%。另外两个域由未撰写资产的团队分别在 4 天和 7 天内接手。
- **标签**：长程SOP, 外置状态机, 验收门

### 4. Can Agents Keep Up with Time? An Empirical Analysis of Temporal Adaptation After a Conversational Hiatus

- **链接**：https://arxiv.org/abs/2611.17806
- **对应缺口**：跨会话记忆与状态携带 / 长程任务与检查点续跑
- **一句话技术作用**：给跨会话 resume 补一条硬规则：再唤起时必须把当前时间用进计划，而不能只召回旧预约和笔记；能读到时钟却仍按过期安排办事，等于状态没带上。
- **要点**：作者提出 session-rekindling：固定前次对话，只改变回访日期和时间信息的送达方式。五个模型路由、五种时间信息条件下，agent 通常能查询当前时钟，甚至在推理中写明日期已过，却仍常让用户为已过期事件做准备。补上显式时间上下文可降低该错误，直接给出已计算的日期关系则能消除它。跨会话续跑不能只保留旧记录，还要把「现在几点」变成更新后的计划。
- **标签**：跨会话记忆, 时间状态, 会话再唤起

### 5. When Should LLM Agents Forget? Memory Filtering Under Query-Critical Resolver Errors

- **链接**：https://arxiv.org/abs/2611.17338
- **对应缺口**：跨会话记忆与状态携带
- **一句话技术作用**：与「何时该记住」对仗：给持久记忆的删除闸门设默认策略——解析器不可靠时宁可误留也不要误删查询关键事实，避免跨会话状态被清掉后任务做不完。
- **要点**：硬删除在解析完美时有 +0.186 到 +0.230 的收益，在最低测试可靠度下变为 -0.176 到 -0.181 的损失；误删伤害显著大于误留。冻结的 102/102 划分上，与部署匹配的门控准确率 0.655，始终硬删除 0.641，知情预言机 0.662。全局准确率交叉点依赖金标，只宜作诊断。删除应作成本敏感决策：先验证查询关键误删风险，否则默认不删、做无标签保留。本篇提交日期较早，本窗口（2026-11-16 公告）首次出现。
- **标签**：跨会话记忆, 遗忘门控, 误删风险

### 6. Actor, Judge, or Teacher? Understanding Decision Models in Long-Horizon Agents

- **链接**：https://arxiv.org/abs/2611.17167
- **对应缺口**：多轮工具规划与自我纠错 / 轨迹级声称-vs-做成评测
- **一句话技术作用**：不要只用决策模型当场选下一步；用看完整轨迹的法官做过程奖励，能把「先做该做的子目标」教进小策略，减少长程任务被容易但错误的岔路带走。
- **要点**：在 ALFWorld 上，六个模型当 actor 时都会被更容易的子目标从必须先做的子目标上拉开；当看到完整轨迹的法官时，同一批模型会给迈向该先做子目标的步骤记功，且「这一步是否有帮助」比「任务会不会成功」更能分开有用和无用动作。JEV 作教师时，把 Qwen2.5-1.5B 策略在 GRPO 之上从 ALFWorld 72.8% 做到 82.9%、WebShop 56.8% 做到 71.4%。
- **标签**：长程规划, 轨迹法官, 过程奖励

### 7. WindowsWorld: A Process-Centric Benchmark of Autonomous GUI Agents in Professional Cross-Application Environments

- **链接**：https://arxiv.org/abs/2604.27776
- **对应缺口**：Computer-use/GUI agent 任务完成率评测 / Windows/进程编排与可靠取消
- **一句话技术作用**：给 DSH-Windows / 家用机场景补一条跨应用、带中间检查的专业工作流尺子：不能只报单应用完成率，跨 3 个以上应用的条件推理和早期子目标卡住才是真正缺口。
- **要点**：本篇为回补。181 题、平均 5.0 个子目标、覆盖 17 个常用桌面应用，其中 78% 本质是跨应用，由 16 个职业驱动生成并带中间检查。领先 CUA 在跨应用任务上成功率都低于 21%，远差于简单单应用题；需要在至少 3 个应用间做条件判断与推理的任务，往往在早期子目标就停住；步数远超人类上限仍常失败。
- **标签**：CUA完成率, Windows, 跨应用工作流

### 8. ToolCUA: Towards Optimal GUI-Tool Path Orchestration for Computer Use Agents

- **链接**：https://arxiv.org/abs/2605.12481
- **对应缺口**：多轮工具规划与自我纠错 / Windows/进程编排与可靠取消
- **一句话技术作用**：让 DSH 在「鼠标点击」和「直接调工具/API」之间学会选更短、更稳的路径，而不是整条任务都靠 GUI 硬点；用路径级奖励把编排做成可训练的切换策略。
- **要点**：本篇为回补。先用静态 GUI 轨迹合成接地工具库并生成交错 GUI-Tool 轨迹，再以 SFT + 单轮 RL 抓住切换点，最后在高保真环境做在线 Agentic RL，奖励恰当用工具、缩短路径。OSWorld-MCP 上 ToolCUA 准确率 46.85%，相对基线约提升 66%；比纯 GUI 设置高 3.9 个百分点。
- **标签**：GUI-Tool编排, CUA完成率, 路径选择
