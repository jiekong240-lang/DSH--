### 1. PACT: Plan-Action Consistency Training by Preserving Correct Plans and Repairing Actions in GUI Agents

- **链接**：https://arxiv.org/abs/2611.22591
- **对应缺口**：多轮工具规划与自我纠错 / Computer-use/GUI agent 任务完成率评测
- **一句话技术作用**：计划想对了但动作没跟上时，不要用结局惩罚把正确计划一起打死；保护已验证计划、只修错误动作，用来抬升 GUI 多步任务完成率。
- **要点**：GUI agent 常在推理里写出正确的即时计划，却发出执行不了该计划的动作，一次执行失误就能带偏多步流程。结局监督的 RL 若把负优势广播到整段 token，会连有效规划一起惩罚。PACT 在不改原有标量动作奖励的前提下，用参考动作定位执行缺口：对已验证计划的 token 区间屏蔽负策略梯度，并在保持生成推理不变的条件下，用带 stop-gradient 配对权重的偏好替代，让参考动作压过发出的错误动作。相对只看结局的基线，AndroidWorld 任务成功率从 60.34% 升到 68.97%（+8.63 个百分点），AndroidControl High 上基于规则的计划-动作一致性从 83.71% 升到 89.74%（+6.03 个百分点）；迁移到桌面 agent 后，完整 369 题 OSWorld 成功率从 40.92% 升到 44.17%（+3.25 个百分点）。
- **标签**：GUI自我纠错, 计划-动作一致性, CUA完成率

### 2. EVIDENT: Evaluating Evidence Grounding in GUI Agents

- **链接**：https://arxiv.org/abs/2611.20488
- **对应缺口**：轨迹级声称-vs-做成评测 / Computer-use/GUI agent 任务完成率评测
- **一句话技术作用**：不要只看任务表面上是否答完；用证据是否被观察到、声称是否被证据支撑，把假绿和真做成分开。
- **要点**：GUI agent 评测常看网页任务是否完成，但表面成功可能藏着最终答案并未被导航过程中观察到的证据支撑。EVIDENT 是证据驱动基准，含 220 道真实英/韩任务，覆盖语义接地、情境推理和视觉接地，每题附带人工整理的证据元数据，写明必须核验什么。用 TSR、ESR、GSR 分别衡量结果成功、必要证据是否被观察到、声称级证据支撑。商业与开源 GUI agent 上，表面成功和证据接地成功之间存在明显差距，尤以情境和视觉任务为甚。说明现有评测可能高估可靠性，需要同时问「是否作答」和「是否核验」。
- **标签**：声称vs做成, 证据接地, GUI评测

### 3. UIAnchor: Anchoring UI Perception and Action Execution for Reliable Service-Composed Mobile Task Automation with GUI Agents

- **链接**：https://arxiv.org/abs/2611.20753
- **对应缺口**：Computer-use/GUI agent 任务完成率评测 / 多轮工具规划与自我纠错
- **一句话技术作用**：在跨应用、细粒度 GUI 流程里，先核对要点再动手、动手后检查结果，并用逐步状态跟踪做定向恢复，减少漏看控件和点错目标。
- **要点**：通过对可部署 GUI agent 的实地失败分析，作者指出两个主导瓶颈：常漏看或误读可操作控件，以及未核验目标对不对、结果成没成就执行动作。UIAnchor 用两段式 UI 解析提高元素召回与情境语义，并由元控制器做动作前核验、动作后结果感知、逐步状态跟踪和定向恢复。按步数、跨应用范围和 UI 粒度划分 L1–L5，L5 仍超出当前实用前沿。在最难的实用档 L4（20–30 步、多应用、目标小于 100×100 像素，约合常见手机上 5 mm）上，成功率相对 GPT-4o 提高 31.5%、相对 Mobile-Agent-v3 提高 16.6%。在边云协助下约每步 2 秒，与人手操作相当，每步时延最多降 75.5%、能耗降 52.4%，并泛化到未见应用和跨平台 GUI。
- **标签**：GUI完成率, 动作核验, 失败恢复

### 4. From Repositories to Training Environments: Scaling Long-Horizon Coding Agents with Environment Evolution Loop

- **链接**：https://arxiv.org/abs/2611.21152
- **对应缺口**：仓库/项目自动理解与 execution bootstrap / 长程任务与检查点续跑
- **一句话技术作用**：把真实仓库自动变成可验证的「从规格把项目搭起来」环境，并用进化环提高训练价值，用来训能做长程仓库级任务的编码 agent。
- **要点**：现有流水线常在验证后就结束，只能说明环境能用，却几乎不指导如何提高训练价值；递归自我改进又常要等模型 rollout 或训练后再做下游评估，长程任务上成本和反馈延迟会被放大。RepoFactory 把真实仓库转成可验证环境，让 agent 根据语言规格从零搭建完整项目，其 Environment Evolution Loop 用代理反馈优化有效性、结构耦合与实现范围的乘积目标。共产生 10,159 个环境、覆盖 17 个软件领域。用这些环境训练 Qwen3.5-35B-A3B 得到 RepoHorizen-35B-A3B，相对无环境进化，在 NL2Repo-Bench 上的增益从 17.5 个百分点升到 22.6 个百分点，在覆盖长程编码与真实生产代理任务的五个基准上的平均增益从 6.4 升到 8.5 个百分点。
- **标签**：execution bootstrap, 长程编码, 仓库环境

### 5. RIPPLE: Recovery Internalization through Process-Level Policy Learning and Effect-Aware Credit for Long-Horizon Agentic Coding

- **链接**：https://arxiv.org/abs/2610.31276
- **对应缺口**：长程任务与检查点续跑 / 多轮工具规划与自我纠错
- **一句话技术作用**：解决「看出失败、写出像样的批评，却仍沿错误轨迹走下去」：把分阶段恢复（察觉、诊断、纠偏）内化进同一策略，部署时不再另挂批评者。
- **要点**：长程编码 agent 观察到失败并能写出像样的批评，却仍沿同一错误轨迹继续，作者称之为 Critique-to-Action Handoff Gap。RIPPLE 用只看前缀的教师提供有证据依据的恢复监督（不看未来动作或终局），经轻量蒸馏后再用强化学习给反思触发、诊断和纠偏动作分配阶段信用；局部有效性信号门控轨迹优势，避免中间恢复决策无差别继承终局结果。在四个仓库级软件工程基准上，相对基础策略算术平均提高 4.8 分，部署时无需额外批评者。对照实验表明局部、阶段对齐的信用有贡献；匹配前缀的干预显示批评语义会影响随后的纠正。恢复收益集中在前缀已有足够诊断证据、且仓库状态在剩余预算内仍可逆的情形。本篇提交较早（2026-10-22），本窗口（2026-11-18 公告）首次收录。
- **标签**：失败恢复, 长程编码, 自我纠错

### 6. AdMem: Expectation-Grounded Procedural Memory for Long-Horizon Task-Solving Agents

- **链接**：https://arxiv.org/abs/2611.20605
- **对应缺口**：跨会话记忆与状态携带 / 长程任务与检查点续跑
- **一句话技术作用**：不要无结构地堆跨任务经验——那样可能比没有记忆更差；给每一步写期望结果、按实现打分，并用效用驱动召回和淘汰，让过程记忆真正提高完成数。
- **要点**：朴素堆积跨任务经验可能比没有记忆更差：在 AgentBoard 上，工作流归纳记忆在八个域中的七个完成任务数少于无记忆 ReAct；没有外围结构的逐步过程库在 Jericho 上丢掉 ReAct 一半的完成数。AdMem 补上逐步信用分配和条目生命周期：行动前 actor 先承诺期望结果，并行 critic 把实现结果对期望打分，写入带二元奖励和反思的过程条目，信用落到挣到它的那一步，且不需要环境奖励。每条条目带标量效用，在 noisy-OR 奖励模型下在线更新，与情境相似度一起排序召回并驱动淘汰与合并。707 项、八个 AgentBoard 域上，AdMem 完成 441 项，ReAct 388、工作流归纳基线 312；合并增益在双侧 Fisher 精确检验下显著，集中在有可迁移跨任务结构的域。记忆保持为人类可读文本。
- **标签**：过程记忆, 跨任务状态, 效用淘汰

### 7. StaleBench: Isolating Stale Retrieval in Agent Memory, and Pricing the Fix

- **链接**：https://arxiv.org/abs/2611.19752
- **对应缺口**：跨会话记忆与状态携带
- **一句话技术作用**：同一事实有多个版本时，不能靠相似度检索挑「现在」的值；要用货币性标签评检索，并在写入和查询两侧做实体解析，避免过期记忆把后续任务带偏。
- **要点**：agent 长期存事实后，同一事实会留下多个版本。面对「X 现在为哪支球队效力」这类不点明取值的问题，相似度检索无法偏好当前版本，因为每个版本都匹配查询点名的实体。StaleBench 在 892 条真实更新事实上隔离这种过期检索失败，货币性标签来自来源（经由 TempLAMA 的 Wikidata 有效年份），从不来自检索分数。中心结果是检索指标可能把记忆策略排反：某保留策略与其「全留」对照在每个测试查询上都把同一条陈述排到第 1，但在不给出日期时，两名阅读器的准确率分别相差 29.5 和 65.6 个百分点。作者增加的 Contamination@5 能正确排序，而 current@1 / current@5 不能。撤掉陈述自带的词汇锚会让已部署的键控机制损失数十分的新鲜度；在写入路径和查询两侧做实体解析能挽回大部分损失。Mem0、Graphiti、LangMem 和复现的 ERASE 对取代关系的处理各不相同，没有一种打分约定能描述全部四个系统。
- **标签**：过期记忆, 跨会话状态, 检索评测

### 8. LEDGER: Auditable Agent Memory Under Change

- **链接**：https://arxiv.org/abs/2611.20927
- **对应缺口**：跨会话记忆与状态携带
- **一句话技术作用**：事实会变、来源可信度不同、用户会要求删除时，用显式规则决定当前值、信任谁、删什么，并同时给模型和审计看证据，而不是只打最终答案分。
- **要点**：现有记忆系统多在固定历史上评测，且只给最终答案打分。LEDGER 由语言模型提议事实，由显式规则决定哪个值是当前的、信任哪个来源、删除什么；每条事实保留来源和它成立的时段。LEDGER+EP 还会对账本未覆盖的问题检索原始对话轮次，并在删除时清洗这些轮次。在同一答题模型和提示下，于合成的多会话编码 agent 工作负载和 LongMemEval 的 210 题子集上，同时给记忆送给模型的证据和答案打分。编码工作负载上，LEDGER+EP 在回退模式下五个开发种子正确率 94.3%、五个留出种子 91.1%，最强基线「全量回放」为 82.1% 和 83.3%。当删除请求只描述该事实时，在所有评测探针中，已删除的值都没有进入系统送给模型的证据。在 LongMemEval 上，LEDGER+EP 在增强模式下观测准确率与全量回放相同（74.8%），上下文只有后者的 1%。主要限制是编码工作负载为作者自建的合成集；在 LongMemEval 上，最强系统之间的差异落在置信区间内。
- **标签**：可审计记忆, 状态更新, 跨会话

### 9. When the Cheapest Feasible Router Fails: Auditing Deployment Commitments in Cost-Aware LLM Routing

- **链接**：https://arxiv.org/abs/2611.20417
- **对应缺口**：成本约束下的级联路由（少钱也要把任务跑完）
- **一句话技术作用**：审计通过的「最便宜可行」路由，到新请求上仍可能违约；部署前要用承诺审计在「上线最便宜方案 / 换一个有证据支撑的备选 / 暂缓」之间做选择，避免省钱把活跑砸。
- **要点**：成本感知路由常选满足经验风险和覆盖约束的最便宜策略，但通过审计的路由器仍可能在新请求上违反既定服务契约。作者用互斥的构造、审计和测试样本研究这一部署承诺决策。在 19 个 RouterBench 任务族上，审计意义下最便宜的可行路由器有 91.82% 的机会被部署，但其中 32.22% 的部署会在留出集上违约。Menu-Aware Routing Commitment（MARC）用审计证据和可接受的服务成本容差，决定保留表面上的赢家、改上有支撑的备选，或暂缓；其实用的按策略变体 MARC-P 把观察到的条件失败降到 0.73%，部署率 85.79%，服务成本更高。固定裕度和形式化风险控制程序是有竞争力的替代。嵌套审计展示了增加证据如何改变可部署策略集；学到的语义路由也出现同样的承诺失败。
- **标签**：成本路由, 部署承诺, 级联降级

### 10. AgentLens: Revealing The Lucky Pass Problem in SWE-Agent Evaluation

- **链接**：https://arxiv.org/abs/2605.12925
- **对应缺口**：轨迹级声称-vs-做成评测
- **一句话技术作用**：测试通过不等于过程可靠：要把「瞎试却碰巧通过」的 Lucky Pass 从扎实轨迹里分开，不能只按通过率给编码 agent 排名。
- **要点**：软件工程 agent 评测被二元信号主导：最终补丁是否通过测试，从而把有章法的解和混乱试错视为等价。作者表明这种等价在经验上不成立。他们评估了八个模型后端在 60 道 SWE-bench Verified 任务上的 2,614 条 OpenHands 轨迹；其中 47 题有足够通过轨迹来构造任务级过程参考，形成 1,815 条轨迹的评测子集。该子集的通过轨迹中，10.7% 出现 Lucky Pass：回归循环、盲目重试、缺少验证，或探索、实现与验证在时间上错序。AgentLens 做过程级评估，并发布 AgentLens-Bench：1,815 条带质量分、浪费信号、分歧点和 47 个任务级 Prefix Tree Acceptor（PTA）参考的轨迹。质量分把通过轨迹分成 Lucky、Solid、Ideal 档，并把 Lucky Pass 再分成五种反复出现的机制。八个后端的 Lucky 率从 0.5% 到 23.2%，部分模型在改用质量分而非通过率排名时会移动多达五个名次。本篇提交较早，本窗口（2026-11-18 公告）首次收录。
- **标签**：声称vs做成, Lucky Pass, 轨迹评测
