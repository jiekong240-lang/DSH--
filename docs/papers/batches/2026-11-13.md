## 新增条目（5）

### 1. Coati: Host-Grounded Execution for Installable Mobile GUI Agents

- **链接**：https://arxiv.org/abs/2611.02644
- **对应缺口**：轨迹级声称-vs-做成评测 / 跨会话记忆与状态携带 / 成本约束下的级联路由
- **一句话技术作用**：把 claim-gate 从模型自报改成宿主证据审计（证据不足标 unverified），并给 memory-drive 与 free-ladder 一套「只记已验证经验 + 简单步走快路径」的落地组合。
- **要点**：VerifyLoop 用界面变化、跨应用结果屏和循环进度核对动作与完成声称；AppMemory 只在任务通过完成审计后写入按应用手册；路由快执行器让轻量选择器处理有把握的简单步，循环由宿主按一次规划重复。AndroidWorld 116 题、同一 Gemini 3.8 Flash 骨干下三试成功率 86.5%，领先同条件 Artemis 77.6%；假完成声称约降三分之一；日常任务中位时延降 39%，循环任务快 2.8–5.4 倍且 token 降 6–9 倍；重复深路径从 18.5 步降到 6–7 步。
- **标签**：声称vs做成, 宿主证据, 跨会话记忆, 成本路由

### 2. Visual Token Routing: Learning to keep tokens that matter

- **链接**：https://arxiv.org/abs/2611.06854
- **对应缺口**：成本约束下的级联路由（少钱也要把长程任务跑完）
- **一句话技术作用**：给长桌面轨迹降观察成本：在不伤完成率的前提下只保留对下一步动作有用的屏幕区域，服务 free-ladder / 长上下文续跑。
- **要点**：轻量时空路由器按当前与历史截图决定哪些视觉 token 进入语言模型，与模型联合训练。2000 步即可在 OSWorld、CUA-World 与游戏动作预测上对齐全分辨率模型，视觉 token 减少 2.5–5.8 倍，推理成本最多降 3.3 倍、prefill 最多快 2.9 倍；OSWorld 上比降分辨率或其他丢 token 基线最多高 12.8 分。
- **标签**：成本路由, 视觉token, 长程CUA

### 3. ScienceCUA: Resource-to-Skill Construction and Execution-Guided Skill Evolution for Scientific Computer Use Agents

- **链接**：https://arxiv.org/abs/2611.03238
- **对应缺口**：仓库/项目自动理解与 execution bootstrap / 多轮自我纠错
- **一句话技术作用**：给 DSH 打开专用软件（含 FreeCAD 等）提供「文档→可执行技能→失败轨迹修订、验证后才入库」的 bootstrap 路径，而不是把整本手册塞进上下文。
- **要点**：手册提炼为 Skills（任务流程）与 References（命令/语法/约束）；用真实环境执行反馈对照成败轨迹，修订或增补条目，且只在目标环境反复验证后入库。审计修正 ScienceBoard 得到 ScienceBoard-Verified，并另设与测试集不相交的演化任务集 ScienceBoard-VE。初始库相对基座平均成功率最多 +7.23 个百分点，演化后总提升最多 +17.12 个百分点。
- **标签**：execution bootstrap, 技能演化, 科学软件CUA

### 4. Repeating Work Can Lower Energy per Successful Goal in LLM Agents

- **链接**：https://arxiv.org/abs/2611.10315
- **对应缺口**：长程任务与检查点续跑 / 可靠取消与失败恢复
- **一句话技术作用**：给 resume-task 提供可量化选择：早失败宜整任务重启，晚失败宜保留进度续跑，能恢复会话+工具状态时优先只回滚被打断的那一轮，并用成功完成的代价（含失败能耗）而不是单次能耗做决策。
- **要点**：用 EpG（含失败跑能耗）比较重启、续跑、只回滚被打断一轮、grounded resume，各配保留/清空前缀缓存。保留缓存时，早期失败重启比续跑 EpG 低 22%，晚期失败续跑比重启低 24%；工具失败的早、晚期都是只重复被打断那一轮的 EpG 最低。暖缓存让需重算的 prompt token 减少 86%，但恢复能耗只降 8%（上下文至 7333 token）。
- **标签**：检查点续跑, 工具失败恢复, EpG

### 5. Same Error, Different Recovery: How Delivery Changes LLM Agent Behavior

- **链接**：https://arxiv.org/abs/2611.11581
- **对应缺口**：多轮工具规划与自我纠错 / 工具失败后的恢复策略
- **一句话技术作用**：升级 DSH 工具失败处理：不要只把原始 stderr 塞回 tool 消息，应保留失败交换并在新一轮给出分类指导（可重试 / 需改参 / 应停止上报），避免模型空转重试或假装做成。
- **要点**：同一错误文本因投递位置、是否保留失败往返、是否新开用户轮次，会导致不同下一步。13 个 3B–70B 开源模型的预注册对照显示，保留失败交换并追加用户轮次可避免 Llama 在不可恢复错误上停不下来。作为可选恢复层，ToolMaze 显式错误上 7–8B 成功率 +14.2、32–70B +10.5 个百分点；Loud/Quiet 无显著增益。客户端若已知精确故障类型仍更强。
- **标签**：自我纠错, 错误投递, 工具失败恢复
