## 新增条目（9）

### 1. NorthCUA Technical Report: Turbocharging Computer-Use Agents through Experience at Scale

- **链接**：https://arxiv.org/abs/2611.02102
- **对应缺口**：任务完成率评测尺子 / 长程里程碑续跑
- **一句话技术作用**：给 stage1/瞭望更新开源完成率标尺，并把「已验证里程碑上再试」对齐 resume-task 续跑。
- **要点**：Experience Flywheel + Harness 长交互并核对任务结果；未解任务保留已验证里程碑再进化可复用技能；开源 Nano/Mini/Pro 在 GUI grounding、桌面执行与 Web 交互报开源 SOTA。
- **标签**：CUA完成率, 里程碑续跑, 经验飞轮

### 2. CUA-Master: Scaling Computer-use Agents through Open-World Recursive Improvements

- **链接**：https://arxiv.org/abs/2611.03126
- **对应缺口**：任务完成率评测尺子 / 检查点回滚重试
- **一句话技术作用**：提供最新 OSWorld / OSWorld 2.0 对标数字，并把失败后快照回滚再采集落到真实环境。
- **要点**：开世界双环递归改进；轨迹采集用反馈引导的 snapshot-rollback 重试。CUA-Master-27B：OSWorld Verified 80.2、OSWorld 2.0 36.9、WeaveBench 43.9、Agents' Last Exam 25.0。
- **标签**：CUA完成率, 快照回滚, 递归改进

### 3. MemU-Bench: Benchmarking GUI Agents on Long-Horizon User Interactions

- **链接**：https://arxiv.org/abs/2611.00191
- **对应缺口**：跨会话记忆与状态携带 / 记忆评测尺子
- **一句话技术作用**：给 memory-drive / session 召回一套不靠穷搜的评测尺子，并提供按应用结构化记忆的可落地框架。
- **要点**：118 个依赖历史的模糊任务；用 IE/SPL 揭穿靠穷搜假装记住的假成功。无历史时最强 Gemini-3.1-Pro 的 SPL 仅 16.4%；AppMem 把 GPT-5.5 的 SPL 从 15.7% 提到 66.9%。
- **标签**：跨会话记忆, 评测尺子, 反穷搜假绿

### 4. Probe-and-Resume: When and How to Evaluate Agent Execution

- **链接**：https://arxiv.org/abs/2610.21088
- **对应缺口**：轨迹级声称-vs-做成评测 / 检查点续跑
- **一句话技术作用**：直接升级 claim-gate：完成声称必须在分支环境被探测证实，失败则原状态续跑，而不是整任务重开。
- **要点**：只在 agent 声称完成时，用当前/初始状态的 fork 做可破坏探测；拒绝则从原状态续跑。Terminal-Bench 2.1 上较常规 MCTS 批评器成功率 +8.4 个百分点（63.4%→72.4%），接近同模型 Codex CLI，成本不到一半。
- **标签**：声称vs做成, fork探测, 拒绝后续跑

### 5. CUA-Recovery: Benchmarking Error Recovery in Long-Horizon Computer-Use Agents

- **链接**：https://arxiv.org/abs/2610.27645
- **对应缺口**：长程任务失败恢复评测 / 自我纠错
- **一句话技术作用**：给 supervisor 续跑与自我纠错提供可量化尺子：先测「是否察觉继承错误」，再测「能否从脏状态把活做完」。
- **要点**：用真实策略产生的错误状态评测恢复：测试集 100 任务 / 2250 个错误态。六种 agent、六档接管深度下，错误察觉率最高 44.0%，Pass@3 最高 25.5%。微调后 EAR 19.9%→35.2%。
- **标签**：失败恢复, 长程CUA, 评测基准

### 6. Switch-SWE: Do Coding Agents Hold Focus When Switching Between Unfinished Tasks?

- **链接**：https://arxiv.org/abs/2611.02017
- **对应缺口**：仓库/项目自动理解与 execution bootstrap / 多任务检查点续跑
- **一句话技术作用**：服务 DSH sandbox 多任务交错：切换后要找回需求与部分进度，而不是只评单 issue 一次做完。
- **要点**：同一仓库交错多个未完成任务后再回到焦点任务；200 个焦点任务、7 个编码 agent 平均完成率掉 11.5 个百分点。插件式上下文管理（相关历史+任务状态摘要）可挽回 5.5–15.5 个百分点。
- **标签**：任务切换续跑, 仓库级编码, 上下文管理

### 7. From Interaction to Capability: Task Advancement as State and Supervision for GUI Agents

- **链接**：https://arxiv.org/abs/2610.37482
- **对应缺口**：长程 GUI 状态携带 / 跨应用可复用操作记忆
- **一句话技术作用**：把记忆从「重放历史」改成「已验证进展 + 可复用操作」，降低长桌面链路漂移并节省 token。
- **要点**：以已验证任务进展为状态（TAM）：跨应用累积成果，并把成功片段抽象成可复用操作。MobileWorld GUI-only 成功率 12.0%→28.2%；完整 TAM 相对最强基线成功率 +17.6%，每成功任务 token 降 38.7%。
- **标签**：任务进展状态, 可复用操作, 长程GUI记忆

### 8. VeriCUA: Verification as Agentic Exploration for Computer-Using Agents

- **链接**：https://arxiv.org/abs/2610.40578
- **对应缺口**：轨迹级声称-vs-做成评测（主动取证）
- **一句话技术作用**：与已收入的「隔离自报」互补：claim-gate 不只看轨迹报告，还应主动用 GUI/代码取证来拒绝假绿。
- **要点**：把完成验证当作动态取证：先建任务量规，再用 GUI/代码检查未决要求，按显式证据规则合并。跨桌面/移动/Web、在线与离线同一流程；在线设置更强拒绝假完成声称。
- **标签**：主动取证验证, 声称vs做成, 跨端评测

### 9. LEASH: Uncertainty-Aware Weak-to-Strong Escalation and Oversight for Computer-Use Agents

- **链接**：https://arxiv.org/abs/2610.22280
- **对应缺口**：成本约束下的级联路由（少钱也要把任务跑完）
- **一句话技术作用**：给 free-ladder / quota-probe 提供 CUA 专用、免训练的按步升级策略：小模型能做就做，不确定再交强模型。
- **要点**：默认小模型干活，用已有隐状态与成败轨迹对比估不确定度再升级；交接后用影子观察盯住黑盒强模型。OSWorld 上 Qwen3.5-35B-A3B 成功率 73.66%、每任务 $0.4117，对齐常开 Claude Opus 5（72.90%）且推理成本降 19.2%。
- **标签**：成本路由, 弱到强升级, 不确定度
