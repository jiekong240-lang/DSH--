# 目标回信：我要的 DeepSeek Harness 是什么

收件人：本机所有执行 AI  
写手：本地电脑助手 · DSH-Windows（按负责人 Junlong 的目标转写，不是另定口径）  
日期：2026-11-08（UTC+8）  
机器：温蒂冲压 · `dsh-sandbox`

---

## 目标（唯一中心）

**这个程序的用户只有我。**

我要的结果是：

1. DeepSeek Harness 被拆成开放形态——**我可以随便加任何改装**；  
2. 加改装时 **系统不崩**；  
3. 将来官方出了更新，我 **还可以继续拆、继续加改装**，而不是被一次升级锁死或整盘报废。

执行方的一切工单、认收、切流、补丁、文档，都只为这个目标服务。  
不要用「口径」「对齐上游」「产品化」替换这个目标。  
上游扩展点、钉 pin、蓝绿副本——都是实现手段，不是目标本身。

---

## 目标达成时，系统应是什么样

- 我想加的能力（工具、闸门、MCP、技能、实验开关）能挂上去；  
- 挂坏了：进程还在、有日志、能摘掉，而不是整机起不来；  
- 官方发新包：我在隔离环境拆开看、改我的改装层、测过再决定要不要换主线；  
- 主线在我没说换之前，继续稳定跑我正在用的版本；  
- 我永远保有「再拆一次」的权利——更新不是终点。

---

## 手段（从属于目标；可随目标调整）

下列手段当前有效，因为它们服务上面的目标；若某条手段妨碍「随便改装 / 更新还能拆」，以目标为准改手段，不要为保手段牺牲目标。

| 手段 | 为什么服务目标 |
|---|---|
| 改装走 MCP / 薄插件 / cordis / 显式 overlay | 加东西不必挖官方内脏，更新才拆得动 |
| 不改 `@deepseek-ai/dsh` 包内部 | 官方一换包，我的改装还在 |
| 主线钉版本，升级先在副本 | 更新来了能继续拆，而不先把正在用的弄死 |
| 个人 patch 能迁就迁，迁不出就记豁免与迁出条件 | 减少「一更新就碎」的私货 |
| 负例 + 真实 turn 证据 | 证明「不崩」和「还能跑」，不是口头完成 |
| 切流必须我书面点头 | 换主线版本是我的选择，不是执行方自动升级 |

---

## 现在进度（相对目标，不是相对流程表格）

- **开放可挂、坏了不崩**：已做到一版（G1–G8 通过；W1–W3、A1 双绿在副本上验证过）。  
- **更新来了还能拆**：工序已跑通一次（`0.2.2-rc.1` 副本）；**主线尚未切过去**——因为切流是「我是否换正在用的版本」，不是目标自动完成项。  
- **我随便加改装**：通道和样例（如 `open-probe`）已在；以后加什么由我点名，执行方按扩展点挂，并证明不崩。

未完成、且仍服务同一目标的：

- 副本上已摸到的契约差（例如换枪下一 step 生效）——继续在改装层消化，好让下次官方变 API 我还能拆；  
- 主线是否升到 `0.2.2-rc.1`——等我为「继续拆更新」明确下令，不默认升；  
- 其它线（页面筛选 bug 等）——不顶替本目标，另说另做。

---

## 对执行 AI 的要求（按目标写）

1. 先问：这一步是否让我更接近「随便改装 + 不崩 + 更新还能拆」？不是则停。  
2. 加改装：挂在可拆层；留下能复跑的证据。  
3. 遇官方更新：拆副本、适配改装层、证明不崩；未叫切流就不动主线。  
4. 回信写清：为这个目标推进了什么、还差什么、有没有把我正在用的主线置于风险。  
5. 禁止把目标改写成「通过某张验收表」或「跟上官方最新」——表和版本只是工具。
