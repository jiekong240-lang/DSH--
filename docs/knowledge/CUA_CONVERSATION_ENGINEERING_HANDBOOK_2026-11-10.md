# CUA 历史技术对话 → DSH-- 工程知识手册（2026-11-10）

**文档性质**：多轮技术讨论提炼出的工程知识与验收规范；不是论文原文、代码审计或实验报告。来源为可检索的历史 ChatGPT CUA 讨论摘要、当前对话及本仓 GitHub 文档。没有访问用户电脑硬盘、未上传的本地论文或真实运行时。以下不作逐字引语；设计与事实严格分开。

**长期目标**：基于官方 DeepSeek Harness（主要推理端 DeepSeek API），开发家用 Windows Computer Use Agent，最终能准确操作电脑、独立开发程序，做到“理解真实仓库→写代码→检查→运行测试→根据真实报错修复→回归→交付可独立重开的可用作品”。论文、失败复现和工程经验也是长期知识资产，但不能代替产品完成。

**去重与范围**：main 已有 docs/papers/INDEX.md、docs/references/CUA_FRONTIER_REFERENCES.md、docs/CUA_ARCHITECTURE.md。PR #2 正在归档 2026-11-09 对话 PDF 与 T0–T6 规范；PR #3 正在修 CUA Coding Loop、MCP、UIA、FreeCAD、监控。它们在本次检查时均未合并；本文不重复论文清单，不假定 PR 中代码已在 main。本次 main SHA：6ae031594bcaeca6259c06a38fde7d8b5ba4d718。DSH-- 与 DSH-Windows/dsh-sandbox 是不同工作范围，不可互相宣称完成。

## 1. 核心架构和不可变约束

1. 官方 DeepSeek Harness 是底座，DeepSeek API 负责主要规划推理，执行/测试/验收由工具层负责。不得修改官方 Harness 核心；只通过实际版本支持的 plugins、skills、MCP 和配置叠加接入。接口名称和 schema 必须读当前版本后确认。
2. 先真实仓库 SHA、OS、依赖、测试入口、实际报错，再设计修复。旧 expect 冲突、旧日志、历史文章仅为候选；先重放真实 surface，确认仍存在才改。
3. 单 Agent 先交付第一个可运行产品，再把 manager-worker、蜂群、多 Agent 并行作为有对照组的研究变量；不能靠增加角色掩盖基础执行缺陷。
4. 真实执行与模型声称分离：计划不等于执行，执行不等于产物，产物存在不等于独立验证。仅 Verified 可算完成；未知和真机未测写 Pending。
5. 首个产品交付前不无限扩张安全研究，但必须保留既有授权、密钥、危险动作门控、不可逆动作确认与不修改官方 DSH 的约束。
6. 知识库可先行：公开论文、官方文档、工程源码、论坛经验、失败案例都可以收集；原始来源与可复现性优先于 AI 自行编造“史诗级论文”。

## 2. 高质量自主编程闭环（优先级高于扩充多 Agent 角色）

流程：明确用户目标与可观察的成功条件 → 读取真实仓库和依赖 → 建立基线（SHA、测试数、退出码、stderr）→ 检索相关代码/文档/论文 → 制订小步修改计划 → 在隔离工作树编辑 → 检查 diff → 跑测试 → 按真实错误修复 → 回归 → 保存交付物 → 关闭并独立重开读回 → 输出证据。

T0：文件变更与作用域检查；T1：语法/编译；T2：类型/静态检查；T3：单测；T4：真实模块集成；T5：端到端用户任务；T6：独立交付验收。小步迭代按影响面选择测试，最终验收不能只靠 Mock。

禁止假绿：删断言、改预期、跳过失败测试、用零测试退出码、截图变化、工具返回 ok 或第二模型夸奖代替验收。每轮记录命令、cwd、SHA、退出码、测试数、stdout/stderr、产物路径/哈希。重复失败没有新证据、预算耗尽、schema 未知、写操作回执不明时停止并报告阻塞。

**建议任务合同字段（提议，非现有运行时 schema）**：task_id、goal、repo、base_sha、allowed_paths、verify_argv、baseline_evidence、acceptance、risk_class、approval、max_rounds、time_budget、rollback_point。**建议交付报告字段**：status、base_sha、result_sha、diff、test_commands、exit_codes、artifact_path、reopened、readback、evidence_paths、known_gaps。

## 3. TS16：规划—执行—重规划

研究候选包括 UFO² HostAgent/AppAgent、Agent S2/S3、ReAct、Plan-and-Execute、LLMCompiler、模板检索、大小模型分工与 checkpoint。它们是比较对象，不应全部引入。

最小实现：短计划（每步含 precondition/action/postcondition/risk/timeout）→ 实时观察 → 执行一步 → 独立观察后置条件 → 必要时重规划。仅在状态改变、工具失败或假设失效时重规划，避免每步全量大模型重算。必须比较任务完成率、误报、平均步数、耗时、token、重试和人工介入。没有实验不得声称成功率提高。

CUA 三通道优先级：能用程序化 API/文件/CLI 时先用确定性接口；GUI 再用窗口、焦点、UI Automation；视觉截图用于语义缺失时的辅助定位。文本模型收到截图路径不等于真的看见像素。坐标必须绑定真实新鲜观察；目标不唯一、窗口变化、状态陈旧则停止或重新观察。

## 4. TS18：诚实、反谄媚与完成状态校准

推荐状态：Planned、Executed、Produced、Verified、Failed、Unknown/Pending。任何模型自述、监督者认可、API 成功响应、工具进程退出码 0 均不能自动晋升 Verified；应由独立验收器检查真实环境。

证据双通道：执行者提供动作日志和原始测试输出；验收器独立读取文件、进程、UI 状态、关闭重开后的结果。外部网页核查可验证事实出处，但不能替代运行代码。低成本自检优先真实工具与测试，高风险/不确定才考虑第二模型审查。记录 false-green rate、误判和 token 成本。

报告规则：查不到写“未查到”；没运行写“未运行”；只有 Mock 写“离线接口测试通过”；无法真机验证写“待验收”；不得将拟议方案、推断或论文声称当成本机实测。

## 5. TS19：危险动作人机确认 HITL

危险动作包括删除、发送消息、购买、提权、系统设置、不可逆提交。研究候选：OpenHands approval、Anthropic Computer Use、安全沙箱、浏览器权限与桌面 gated actions；第三方实际接口需要逐项查证。

动作级别：A 只读可自动；B 受限可撤销写入需限定工作区并保留回退点；C 高影响写入需人类一次性明确批准；D 不可判断/权限不足则停止。批准票据绑定 action_id、目标、参数摘要和时限，执行前核销，不能重放。闸门必须在实际执行端，GUI、CLI、MCP、浏览器与后台任务不得有旁路。可撤销动作优先设计撤销。既有授权和密钥保护始终有效。

## 6. TS20：持久化、幂等和断点续跑

目标：崩溃、重启、断网或进程被杀后，不重复发送消息、提交表单、删除文件。推荐状态机：READY → ACTION_PREPARED（先持久化动作意图）→ DISPATCHING → VERIFIED/COMMITTED；回执丢失则 UNKNOWN_EFFECT → RECONCILE，先重新观察后置条件；无法确认时 BLOCKED/HITL，禁止盲目重发。

最小持久数据：task_id、step_id、action_id、工具与参数哈希、pre/postcondition、风险、票据引用、环境指纹、观察时间戳、状态、重试预算、证据路径、最后已确认 checkpoint。文件状态应原子更新并验证落盘；恢复时核对 SHA/文件哈希/UI 当前状态。API 支持幂等键时传稳定 action_id；GUI 无法保证恰好一次时采用“未知不重放”。

故障注入：动作前崩溃、派发后回执前崩溃、验证后提交前崩溃、文件半写、网络超时、窗口已变化、进程重启。测量重复副作用次数、误判完成、恢复率和日志完整性。共享桌面单写入租约失败应停止，不能无锁继续。

## 7. Grok Bot 看护者与编程 AI 的职责

历史讨论中的 Grok Bot 是监督者/看护者，控制 WorkBuddy 或其他编程 AI 做科研和工程，而不是让人手工写所有代码。

Grok Bot：拆任务、调度、核对进度和证据、监督预算与风险、安排复测；不代替独立验收。Coding Agent：实际读仓库、编辑、运行检查、根据报错修复，不能改测试造绿。DSH/DeepSeek API：规划和工具调用，不把模型答案当环境事实。验收器：从真实文件/应用/日志独立核查。人类：目标与高影响动作审批。

消息合同建议：task_id、goal、base_sha、worktree、allowed_tools、acceptance、budget、risk、status、evidence_paths。多 Agent 实验在相同任务、预算、测试器下比较单 Agent、串行角色、共享工作区和隔离工作区；共享桌面必须串行化键鼠写入。无对照实验不宣称蜂群增益。

## 8. 论文知识库与工程资料的采集规范

用户策略：先把某领域高质量公开论文、技术论坛、官方文档、开源实现、demo 和失败案例放到 GitHub；由 Agent 拉取、阅读、对照、复现，形成可长期复用的工程资产。比“凭空让 API 变聪明”更重视证据积累。

每条资料记录：原始标题、作者/版本/日期、URL、来源类型、许可证、原文定位、核心主张、局限、适用环境、对应模块、可执行复现步骤、测试命令、预期与实测、失败原因、阅读深度（全文/摘要/未读）、是否独立复现。不得把 AI 生成的“50/5000 篇论文”当真实公开论文；版权不明优先收索引、引用与摘要，不批量上传第三方全文。

整理流程：原始资料只读入库 → 去重 → 分类 → 真实性核查 → 知识卡 → 模块映射 → Agent 实际复现 → 保留成功与失败日志 → 人工/监督者复核。整理完必须说明哪些读过全文、哪些只看摘要、哪些未读、哪些链接失效，并给出有依据的观点和建议。所谓“100% 已读”需要文件清单、哈希、阅读记录及内容理解抽查，不接受口头声称。

建议继续维护已有 docs/papers/、docs/references/；本文存 docs/knowledge/。未来可新增 docs/reproductions/、docs/evidence/，但先不要无意义地扩张目录。

## 9. 子项目的可复用验收合同

**FreeCAD**：核实安装版本与 Python API/CLI → 创建参数化几何 → 验证对象数、几何有效性与体积 → 保存 FCStd → 关闭 → 独立重开 → 导出 STEP 并读回。路由测试或生成脚本不等于真实 CAD 模型完成。

**工业级 PPT**：要求理解材料上下文、选版式与套件、视觉一致、可编辑文字图表、动画与特效、渲染审阅、PPTX 保存/重新打开。ComfyUI/Z-Image Turbo 等只是素材生成候选，背景图不能冒充可编辑幻灯片。需检查字体、版式溢出、动画兼容和跨页风格。

**8GB VRAM 的 30B 本地模型**：研究量化、GPU/CPU 分层、KV cache、上下文长度、tokens/s、首 token 延迟、显存峰值、许可证和实际任务质量。“能加载”不等于“速度可用”。保留硬件环境与真实测量脚本，不编造结果。

**本地视频与语音**：按成功复现 → 提速 → 稳定回归 → 分辨率/质量挑战推进，记录真实输出、耗时、失败率。Linux 蜂群 Agent 的多写入者协作思想可迁移，但 Windows UIA/PowerShell 代码不能直接当 Linux 实现。

## 10. 可执行验收矩阵

| 任务 | 真正通过的证据 | 常见假绿 |
|---|---|---|
| GUI 唯一目标点击 | 真实窗口/UIA 定位与动作后状态 | 只有鼠标命令 ok |
| 长文本输入 | 独立读回精确内容 | 截断、快捷键误触发 |
| 记事本文档 | 创建、保存、关闭、重开、读回 | 只显示截图 |
| 修复代码 | 基线红、真实 diff、真实测试绿 | 修改断言、跳过测试 |
| 多文件产品 | 构建、运行、功能测试、独立验收 | 仅单文件替换 |
| 断点恢复 | 进程中断后副作用不重复 | 重复发送/提交 |
| 危险动作 | 绑定动作的一次性批准证据 | 无审批即执行 |
| FreeCAD | FCStd/STEP 原生重开和几何检查 | 仅生成脚本 |
| PPT | 可编辑 PPTX 重开并检查内容/动画 | 只有图片 |
| 多 Agent | 同任务同预算对照结果 | 无基线却称提升 |

拟议指标：独立完成率 R_verified、false_green_rate、duplicate_side_effects、recovery_success_rate、cost_per_verified_task、median_time_to_verified。**这里没有任何实际跑数**。

## 11. 可交给 WorkBuddy / Grok Bot 的开工命令（文本，不是已执行操作）

请先完整阅读本文件，以及 docs/CUA_ARCHITECTURE.md、docs/papers/INDEX.md、docs/references/CUA_FRONTIER_REFERENCES.md，并检查当前已合并代码；不要把 PR #2/#3 当作已进入 main。
